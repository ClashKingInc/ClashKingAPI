## Source-backed strike correction

The canonical optional fields exposed an active handler assumption. Original API source at `cf7371e4a32b4a37afd7c80ff83c72ef29b425e4`, `internal/models/v2/strikes.go` and `internal/routes/server/strikes.go:131–185`, accepts omitted reason/author/image as empty strings, omitted rollover as zero, and omitted or zero weight as one. Explicit weights must be integers from 1 through 2,147,483,647. Nonpositive rollover means no expiry. The shared `StrikeRequest` and existing moderation handler now preserve those defaults; optional image data never reaches SQL as `undefined`.

Original creation totals include only active strikes, while the separate summary GET includes expired strikes too. The creation handler now preserves that distinction. As in the original, a failed follow-up summary after insertion does not turn the already-saved strike into a failed mutation; the response reports zero totals in that failure case. A focused failure regression checks one insertion and success, and a disposable SQL regression checks omitted values, zero weight, negative rollover, expired-strike exclusion after creation and inclusion in summary GET. This is not a claim of exact parity for every malformed or extreme JSON input.
