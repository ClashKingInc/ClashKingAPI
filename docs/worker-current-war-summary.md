# Current-war summary for initialization

`currentWarSummary(bindings, tag, now?)` reads current war, current CWL group, and that group's league wars through `CLASH_PROXY`. The initialization assembler owns authentication and the containing response. This helper makes no SQL query, reads no archive, sends no bearer credentials to the proxy, and has no public-network or legacy backend fallback.

The shared `CurrentWarSummary` schema derives its war and group fields from the canonical proxy schemas and explicitly describes every added clan/member statistic. It retains the existing response names, regular-war precedence over `isInCwl`, `war_info.state = "war"`, and `war_tag` on league-war entries. Regular-war information and CWL information can coexist.

Enrichment follows `internal/routes/war.go`: only inWar/warEnded wars count, only each member's first CWL attack counts, bench members have zero statistics, missed attacks count only after a war ends, and missing defenses count in both active states. Clan stars come from each war's side total without the historical standings helper's win bonus. Offensive destruction determines rank after stars; defensive destruction remains a separate field. Member averages, town hall buckets, matchups, and rounding match the Go-generated fixture. Group-roster `townHallLevel` and war-member `townhallLevel` remain distinct official fields, without compatibility aliases.

`enrichClanLeagueIcons` fills missing icon sizes from the pinned static metadata by league name and preserves supplied URLs. The pinned catalog currently has no war-league icons, so missing URLs remain absent rather than being invented. The static lookup also accepts an exact translated name for this existing Go name-based behavior.

## Intentional differences and resource bounds

- The CWL window follows the documented continuous interval from the first day at 08:00 UTC to the eleventh day at 08:00 UTC, exclusive. This fixes Go's accidental reactivation on the twelfth; it is not an externally verified change to the game's schedule.
- Exact ranking ties use ascending clan tag as a deterministic final tie-breaker, replacing Go map-iteration randomness while retaining distinct ordinal ranks.
- Each provider response is bounded to 1 MiB and a 15-second deadline covering headers and body. Non-success, malformed, oversized, and timed-out responses are treated as unavailable, matching the existing best-effort summary behavior. Successful league-war lookups survive failure of a peer lookup.
- League tags are normalized, deduplicated in round order, and fetched with concurrency ten. A group with more than 64 distinct nonzero tags is rejected before fan-out. The helper makes one current-war request rather than Go's duplicate typed/raw fetch.

The helper does not replace historical `cwlStandings`, `officialArchiveWar`, or archive lookup rules. Authoritative Goose 001–013 schema inspection confirms that stored CWL group/member/round data and historical archive APIs are separate concerns; schema 013 adds subject coordination only. The Expo initializer's disposable-Postgres tests exercise this helper using a mocked private proxy binding.

## Offline validation

`workers/api/test/fixtures/current-war-summary.expected.json` is generated by the existing Go `EnrichLeagueInfoForTest` implementation from the adjacent input fixture. From the API repository root:

```sh
go run scripts/generate-current-war-summary-fixture.go --check
npx vitest run workers/api/src/current-war-summary.test.ts workers/api/src/static-metadata.test.ts
```

Omit `--check` to emit an `apply_patch` update for the reference fixture. Tests validate the entire nested result against Go and the shared schema, input immutability, first-attack rules, missed/bench statistics, window boundaries, fan-out ordering/concurrency, and cancellation of a stalled response body. No test invokes production services.
