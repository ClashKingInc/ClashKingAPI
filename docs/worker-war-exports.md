# Worker war exports

`dispatchWarExports` owns the existing public GET `/v2/exports/war/cwl-summary` and POST `/v2/exports/war/player-stats` descriptors from `expo-exports.ts`. Both return a streamed XLSX with `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, attachment disposition, no-store, and nosniff. Neither requires a user or bot identity, matching Go registration.

The CWL export takes `tag`, chooses the month containing that clan's latest CWL war end, includes both date boundaries, and aggregates the requested clan side from the latest 100 wars. The sheet retains Go's title, clan information, member columns, averages and performance score; its league field remains `Unknown`, as in Go. Its filename is `cwl_<clan_name>_<YYYY-MM>.xlsx`.

The player export takes **one** `player_tag`, optional `timestamp_start`, `timestamp_end`, and integer `limit`. This corrects the earlier shared descriptor's unsupported multi-player/stat-filter shape. Positive timestamps are truncated to seconds, nonpositive/missing bounds use epoch and Unix 9999999999, and both bounds are inclusive. Positive limits select newest war-end hits; nonpositive/missing limits request all matching hits within the explicit Worker budgets below. There are no war-type, TH, stars, freshness or season filters on this route. Its filename is `war_stats_<tag_without_hash>.xlsx`. Missing CWL data or player hits returns 404.

## Non-outlined decisions

- `MAX_EXPORT_ROWS=20000` and `MAX_EXPORT_WARS=1000` are centralized in `war-export-workbook.ts`. A larger positive limit returns 400 `Export limit cannot exceed 20000`. An unlimited result exceeding 20000 hits returns 400 `Export exceeds 20000 hits; provide a limit or narrower time range`. Scanning more than 1000 decoded wars, even for a small positive hit limit, returns 400 `Export exceeds 1000 wars; provide a narrower time range`. These are explicit new bounded-runtime constraints, not unbounded Go parity or silent partial exports.
- The worksheet is preflighted against 8 MiB encoded XML and Excel's 32767-character cell limit before response headers. Oversized workbooks return 400 with a request to reduce the hit/time range. Then a pull-driven worksheet/ZIP stream retains neither the complete XML nor complete XLSX binary. A bounded min-heap selects newest hits while the shared archive iterator retains one decoded war. CWL retains only member totals. The archive iterator's existing per-frame limits still apply.
- Filenames preserve Go's space-to-underscore pattern but replace unsafe/non-ASCII header characters and cap length. Source strings use inline text cells, never formulas. Numeric source fields remain numeric; Go's formatted percentage/average strings are preserved. Ties have deterministic tag/attack-order ordering where Go's sort was unspecified.
- `fflate@0.8.3` supplies ZIP streaming only. The runtime contains a small fixed-layout SpreadsheetML writer, not Node filesystem calls or a desktop workbook-authoring dependency. Binary tests unzip and inspect required package parts, rows, MIME, filename, filters and safety failures; a non-visual workerd test verifies the same streaming encoder in the target runtime.

Format references: [Microsoft SpreadsheetML structure](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document) and [fflate ZIP streams](https://github.com/101arrowz/fflate#usage).
